# 2026-11-04

## CBMC: the boot drivers (branch `cbmc`)

- `src/boot/linux.c` and `src/boot/atf.c` were in the trust boundary; now proven
  (`boot-linux` at 32 and 64 bit, `boot-atf` at 64 bit only: the driver builds for aarch64
  only, so the proof lists its word size in a `words` file that `scripts/ci/cbmc.sh` reads).
- Found and fixed F-168, one `bugfix:` commit per driver and bug: the load address entries of
  the ids in the board config were read as u64 without a size check (an id that is not a part
  is never checked by `boot_image_verify_parts`), the OP-TEE arch entry as u32; libfdt read and
  patched the tree up to `fdt_totalsize`, never compared with the dtb part; the initrd cells
  were 32 bit (truncated above 4 GiB on 64 bit); ATF's 32 bit image size truncated a BL33/BL32
  part over 4 GiB; a format mismatch. D-025 now covers the drivers. Unit tests for the linux
  fixes (`test_linux.c`); atf has none (no board enables it), it builds cleanly for imx8dxlevk
  with `CONFIG_BOOT_ATF=y`, also without the U() redefinition warnings now.
- How the proofs stay small: libfdt is a contract on the tree's address and size (the address
  comes from the signed metadata, CBMC can't follow it as a pointer), the header has its load
  address entries at fixed offsets and the harness reads them by constant index. Through the
  getters every read is a choice over 64 slots and 2048 bytes: 5.7M variables, out of memory.
  Shared in `tests/cbmc/stubs/boot_driver.h`. `strcmp` is now in the string models.
- Full run: all proofs pass at both word sizes, all 42 mutants are killed (81 runs, three are
  64 bit only). `boot-atf`, `boot-linux` and `uuid-roundtrip` need more than the 600 s default
  (up to ~1700 s for `uuid-roundtrip` on a loaded machine), so they set their own `TIMEOUT`.
  Asserting `uuid-roundtrip` at constant indices instead of a symbolic one did not help: the
  cost is the symbolic digit count of each conversion, which moves every later write.
- Phase 4, the host API (`tools/punchboot`) against a malicious device: a host mode in
  `Makefile.common` (`HOST = 1`, shim headers in `tests/cbmc/host/`, malloc can fail) and a device
  stub (`stubs/host_device.h`). Four proofs, `host-api`, `host-part-table`, `host-part-rw`,
  `host-boot-bpak`, found F-169 (eight `bugfix:` commits, D-026): unterminated strings the Python
  wrapper reads as `str`, an unchecked malloc, a division by 0 stream buffers, a chunk size of 0
  that hung or silently skipped the file, and a bpak boot that sent memory past a truncated file
  (new `pb_api_boot_bpak_image` with the size; an integration test). Nine mutants, all killed;
  the mutant runner now copies `tools/`. Reading the rest found F-170 (USB ignores short
  transfers; left open for a hardware check) and F-171 (wrapper: u64 block numbers as `int`,
  `size_t` printed with `%i`, UUID and digest lengths unchecked; all fixed, with tests).
- The `linux` unit test read an `fdt64_t` unaligned (UBSan in the container); fixed.

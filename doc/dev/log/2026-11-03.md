  against C11 7.22.1.4 as a reference parser, snprintf per format, uuid), Phase 2 (bio, gpt with
  every path through gpt_ptbl_init, gpt_write_tbl, ab_state, ramlog, tzc380, the image helpers)
  and Phase 3 (boot.c, the command mode gate, one proof per command handler, crypto dispatch).
- Found F-154..F-163. Fixed, one `bugfix:` commit each with the proof as regression test:
  F-070 (stale header pointer), F-089, F-151, F-154, F-155, F-156, F-158 (GPT entries outside the
  disk), F-159, F-160, F-161 (the auth gate failed open on an SLC read error, D-023), F-162 (backup
  GPT written past the disk), F-163. Earlier: F-001, F-150, F-152, F-153 (part).
- Two unit tests asserted the old behaviour (test_slc_errors, test_allocate_pool_full).
- What CBMC 6.6 could not do and the way around it is in `verification.md` (Setup): symbolic

  Ubuntu archive, bpak built from source); the dev container can't reach apt here.
- Then the open ones, each a `bugfix:` commit: F-055 and F-075 (erase range, writable check, a
  block count of 0 erases the whole partition), F-006 (overlapping GPT entries skipped), F-157
  (bio LBAs past the int getters), F-153 (rot_key_idx_to_id), F-066 (der_ec_public_key_data gets
  the key length), F-148/F-149 (bpak getters stop at the first empty slot, size and offset wrap),
  F-065 (load address size, wrap and 32 bit truncation). D-024 (erase, GPT) and D-025 (malformed
  signed headers): no valid request, table or image changes meaning (D-008). New mutants for
  each. The host board now initializes the RoT and SLC first, so the integration tests run.
- Solvers, benchmarked on crc-32 / ih-load-32: MiniSat (default) 24 s / 227 s, CaDiCaL 24 s /
  243 s, Z3 34 s / >600 s, Bitwuzla 104 s / 307 s, cvc5 369 s / >600 s, Kissat 289 s / >600 s.
  About 97 % of the time is the SAT solver, so no solver helps; `--slice-formula` (now in
  Makefile.common) takes ih-load-32 to 132 s. `--full-slice` is a bit faster but experimental.
- Proving the fixed F-065 property took more than 30 minutes. Split into ih-verify-parts (the
  overlap, any layout; `CHECK_OVERLAP` records the range the code checks) and
  ih-verify-parts-read (`part_load_addr`, metadata anywhere). What made the difference: the
  harness has one part and one metadata entry, so `UNWIND 3` is enough (the unwinding
  assertions check it), and the overlap is asserted per `CHECK_OVERLAP` call instead of for all
  five regions at once. Now 10 s / 25 s. `--property <name>` runs one assertion and is the quick
  way to find the slow one.
- F-167: the last expected failures were implementation-defined conversions (the wire result
  code through `uint8_t`, `efi_crc32` through `long`). Fixed in the source with the same bytes,
  so no proof has an `expected_failures.txt` now.
- Dev container built with apt access (cbmc 6.6.0): `pbdev test` 23/23, also with
  `-DPB_SANITIZE=ON`; firmware jiffy and imx8dxlevk build.
